LE BANC MÉMOIRE DE L'ORDI (2026-11-05, Sacha : « le lien Vercel a des latences et prend beaucoup de mémoire sur mon ordi, règle ça de manière durable »)

Le jeu, dans un Chrome headless (vrai GPU, muet, page-cadre de l'ordi à la taille de l'écran de Sacha : 2560×1350 CSS, densité 1,5),
au menu puis en course au pilote auto, puis à l'écran de mort. Il relève à chaque étape :
  · la mémoire des processus Chrome (navigateur, rendu, GPU : WorkingSet, par PowerShell) ;
  · le tas V8 et les tampons ArrayBuffer (Runtime.getHeapUsage), les compteurs DOM ;
  · dbgCout / dbgNette / dbgPerf / dbgToiles / dbgPhotoMem / dbgPalier (les crochets du jeu : copie LOCALE seulement, publie-allege les retire en ligne) ;
  · les tâches longues (PerformanceObserver longtask) ;
  · --infra=1  : la ventilation memory-infra de Chrome par processus et par allocateur (partition_alloc, cc = tuiles du compositeur, v8, webgl, canvas…) ;
  · --geo=1    : les copies JavaScript des géométries de la scène, une par une (dbgScene) ;
  · --vie=1    : (2026-11-07) les géométries montées à la puce et jamais rendues, par nom d'objet et par course (dbgGeoVie) : la fuite d'une course à l'autre ;
  · --couches=1: les couches composées (LayerTree) et POURQUOI elles le sont ;
  · --workers=1: le tas de chaque Web Worker ;
  · --cpu=1    : profil CPU du chargement ; --cpu=2 : accueil → garage et garage → course ;
  · --tas=1    : profil d'allocations vivantes ; --gc=1 : ramasse-miettes forcé avant chaque relevé ;
  · --bloque=sons-banque : bloque une adresse (ablation : « combien pèse la banque de sons ? ») ;
  · --csstop= / --cssjeu= : un CSS injecté dans la page-cadre / dans le jeu (essais de couches) ;
  · --capture=1 [--clip=x,y,l,h] : une capture PNG (au menu et en course) pour comparer deux réglages à l œil ;
  · --son=1 : les effets sonores restent allumés (Chrome est muet) — CCSON.etat() compte les sons résidents, tardifs, perdus, évincés.

LE BANC DES ORDIS LENTS (2026-11-10) : outils/banc-pc/lent.cjs — le jeu sur un PC simulé (--cpux=3 : processeur 3× plus lent ; --gpu=swiftshader : sans carte graphique), course au pilote auto,
durée des images DU JEU par fenêtre de 5 s, cran de l'échelle, résolution, cadence, régime du poste (dbgPoste) et ce que le juge a appris. --oubli=1 = 1re visite ; sans = visite suivante (même --profil).
⚠ Mesurer sur une machine au repos : un autre banc qui tourne fausse tout (le juge baisse alors le régime, à raison).

LANCER (Node ≥ 22, Chrome installé) :
  node outils/banc-pc/serveur.cjs "VERSION PRINCIPALE" 8125          (dans un terminal à part)
  node outils/banc-pc/banc.cjs http://127.0.0.1:8125/index.html --duree=20 --courses=1 --gc=1 --infra=1 "--q=carte=nuages" --tag=essai
  node outils/banc-pc/banc.cjs https://car-cash-git.vercel.app/jouer/ --tag=live   (le site publié : sans les crochets dbg, mémoire seule)
Les résultats (JSON, journaux, profils) vont dans %TEMP%\cc-banc-pc\resultats\ (CC_BANC_DIR pour choisir le dossier) ; le profil Chrome
« chaud » y reste d'un lancement à l'autre (cache des programmes GPU : 4 s de chargement au lieu de 70).
--q=… ajoute des paramètres d'adresse ; « avant » = ?msaa=1&ouvrier=garde (voir LA TOILE SANS MSAA, L'OUVRIER SE REPOSE).

LA MÉMOIRE AU LONG COURS (2026-11-10, jury DIR-02 : « la 10e partie ne pèse pas plus que la 2e ») — memoire.cjs
  node outils/banc-pc/memoire.cjs http://127.0.0.1:8125/index.html --parties=10 --chaines=10 --zone=6 --tag=essai
N parties identiques (le même tour de maps, franchies par dbgSaut comme le vrai portail), relevé à l'écran de mort ; puis N chaînes A-B-A-B dans UNE partie
(--paires=nuages,midi:ville,orage;jade,midi:foret,midi), relevé en fin de chaîne. Chaque relevé suit deux ramasse-miettes : tas JS, tampons ArrayBuffer,
renderer.info.memory (géométries, textures), programmes, audio décodé (tous les AudioBuffer vivants, comptés par WeakRef, et le PCM de CCSON), DOM, écouteurs.
  --trace=1 : OÙ naît chaque géométrie / texture / matière encore vivante (fonction@index.html:ligne), par partie de naissance, et l'origine des tampons audio ;
              un objet né à la partie 3 et encore « à la puce » à la partie 10 est une fuite, un objet de la seule dernière partie est le niveau en place.
  --tas=1   : les allocations JS vivantes par fonction, dernière partie moins la 2e. Le son est allumé (Chrome est muet) : --son=0 pour le couper.
Ces deux options pèsent sur la mémoire : la courbe qui fait foi se prend SANS elles. Profil Chrome et port à part (9461) : il peut tourner à côté de banc.cjs.
