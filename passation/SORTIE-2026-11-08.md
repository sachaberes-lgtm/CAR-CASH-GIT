Demande de Sacha : « plein de petits trucs à régler, une session de 4 heures où le jeu est fixé et toi tu règles tout ce qui manque pour le sortir ».
Base : `origin/main` v1347 → v1358 pendant la session (d'autres sessions poussent : achats StoreKit, boutique, monnaie). Branche de travail : `sortie-2026-11-08`
(trois branches d'agents fusionnées dedans : `sortie-A-gameplay`, `sortie-B-interface`, `sortie-C-economie`). Une session « Débogage complet du jeu » (`debug/ultime`)
travaillait en parallèle sur les maps et les écrans : on ne s'est pas marché dessus (elle a les erreurs WebGL de Jade, la génération des routes de ville et de forêt).

## 1. Méthode
- Un état des lieux de la base : assembleur d'accord, quatre gardes de publication vertes, essai de l'édition App Store vert, site en ligne = `origin/main`.
- Trois agents, chacun dans sa copie de travail et son domaine de fichiers, sur les défauts encore ouverts des audits (`CHASSE-2026-11-07.md` §4-§5, `AUDIT-FINAL-2026-11-05.md`) :
  A gameplay / moteur / rendu · B interface / textes / écrans · C économie / sauvegarde / missions / voitures / son. Chaque point est relu contre le code actuel (beaucoup
  étaient déjà corrigés) puis corrigé avec preuve, ou rangé en « déjà corrigé » / « à trancher ».

  par ces deux drapeaux, qui coupent justement ce qu'un nouveau joueur traverse. Voir la mémoire du projet `banc-premiere-visite-pilote`.
